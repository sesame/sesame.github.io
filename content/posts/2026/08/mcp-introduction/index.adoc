== はじめに

近年、AI モデル単体でのテキスト生成にとどまらず、**「AI エージェントが外部ツールを呼び出し、データベースを検索し、タスクを自律的に遂行する」** ワークフローが急速に一般化しています。

しかし、これまでは各 AI プラットフォーム（OpenAI, Claude, LangChain, 各種エージェント製品など）ごとにツール定義や API 連携の仕様がバラバラで、同じツールを複数の環境で使い回すには個別にアダプターを実装する必要がありました。

この課題を解決するために登場したオープン標準規格が、**Model Context Protocol（MCP）** です。

[TIP]
====
MCP は、いわば **「AI 版の USB / LSP（Language Server Protocol）」** です。
一度 MCP サーバーを作れば、Antigravity、Claude Desktop、Cursor など様々な AI ホスト環境から同じツールやデータソースを共通のインターフェースで利用できます。
====

'''

== MCP の基本アーキテクチャ

MCP はクライアント・サーバー型のアーキテクチャを採用しており、**Host（ホスト）**、**Client（クライアント）**、**Server（サーバー）** の 3 つの主要コンポーネントで構成されます。

[source,text]
----
+----------------------------------------------------------------+
| Host Application (Antigravity, Claude Desktop, IDE など)       |
|                                                                |
|   +-------------------+              +---------------------+   |
|   |   LLM / Agent     |              |   MCP Client        |   |
|   +---------+---------+              +----------+----------+   |
+-------------|-----------------------------------|--------------+
              |                                   | JSON-RPC 2.0
              | (内部連携)                         | (Stdio / SSE)
              v                                   v
+----------------------------------------------------------------+
| MCP Server (GitHub, PostgreSQL, Filesystem, 社内API など)       |
|                                                                |
|   [ Tools (関数実行) ]  [ Resources (データ) ]  [ Prompts ]    |
+----------------------------------------------------------------+
----

=== 3つの役割
1. **Host**: AI アプリケーション本体（Antigravity、IDE、Claude Desktop など）
2. **Client**: Host 内で動作し、各 MCP サーバーとの 1 対 1 のプロトコル通信を管理するクライアント
3. **Server**: ファイルシステムや GitHub、データベースなどの外部リソースを公開する軽量プログラム

通信プロトコルには **JSON-RPC 2.0** が採用されており、メッセージの送受信が標準化されています。

'''

== MCP が提供する 3 つのコア機能

MCP サーバーは、AI エージェントに対して主に以下の 3 つのプリミティブ（基本機能）を提供します。

[cols="1,2,3", options="header"]
|===
| プリミティブ | 役割 | 具体例
| **Tools（ツール）** | AI が呼び出せる実行可能な関数 | リポジトリの検索、PR 作成、SQL クエリ実行、API コール
| **Resources（リソース）** | AI がコンテキストとして読み込める受動的なデータ | ログファイル、DB スキーマ、ドキュメント、画像
| **Prompts（プロンプト）** | ユーザー向けの事前定義されたプロンプトテンプレート | 「コードレビューを実行」「バグトリアージの定型文」
|===

=== 1. Tools（能動的なアクション）
エージェントが自律的に意思決定して引数を組み立て、実行結果を受け取る機能です。副作用（ファイルの書き換えやデプロイ等）を伴うアクションも定義できます。

=== 2. Resources（データの参照）
ファイル URI 形式（例: `postgres://users/schema` や `file:///var/log/app.log`）で識別されるデータソースです。エージェントが必要に応じて読み込み（Read）、文脈に組み込みます。

=== 3. Prompts（対話のテンプレート）
特定のタスクに最適化されたプロンプトのひな型を提供し、ユーザーがスラッシュコマンドや UI から簡単に呼び出せるようにします。

'''

== 通信方式（トランスポート）

MCP では、用途に応じて主に 2 種類のトランスポート機構がサポートされています。

=== 1. Stdio Transport（ローカル実行）
ローカルマシン上で実行ファイルやスクリプトを子プロセスとして起動し、**標準入力（stdin）と標準出力（stdout）** を介して通信します。

* **用途**: ローカルファイル操作、SQLite、ローカル CLI ツール連携など
* **メリット**: ネットワーク設定が不要で高速・セキュア

=== 2. SSE Transport（リモート連携）
HTTP 上で **Server-Sent Events（SSE）** を利用して双方向通信を行います。

* **用途**: クラウド上の共通サービス、社内マイクロサービス、SaaS 連携など
* **メリット**: 複数メンバーで共有する中央集約型サーバーを構築可能

'''

== 実践：Antigravity での MCP 設定方法

Antigravity では、`mcp_config.json` を配置するだけで簡単に MCP サーバーを導入できます。

=== 設定ファイルの場所
* **グローバル設定**: `~/.gemini/config/mcp_config.json`（全プロジェクト共通）
* **プロジェクト設定**: `.agents/mcp_config.json`（特定プロジェクト用）
* **プラグイン設定**: `plugins/<plugin-name>/mcp_config.json`（プラグイン同梱用）

=== 設定例 (`mcp_config.json`)

[source,json]
----
{
  "mcpServers": {
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": {
        "GITHUB_PERSONAL_ACCESS_TOKEN": "ghp_xxxxxxxxxxxxxxxxxxxx"
      }
    },
    "sqlite-db": {
      "command": "uvx",
      "args": ["mcp-server-sqlite", "--db-path", "/data/app.db"]
    },
    "company-infra": {
      "serverUrl": "https://mcp.internal.company.com/sse"
    }
  }
}
----

[NOTE]
====
`command` に `npx`（Node.js）や `uvx`（Python）を指定することで、サーバーパッケージをローカルに事前インストールすることなく即座にオンデマンド実行できます。
====

'''

== 独自の MCP サーバーを作る（TypeScript 例）

公式の `@modelcontextprotocol/sdk` を使用すると、わずか数十行のコードでオリジナルの MCP サーバーを作成できます。

[source,typescript]
----
import { Server } from "@modelcontextprotocol/sdk/server/index.js";
import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js";
import { CallToolRequestSchema, ListToolsRequestSchema } from "@modelcontextprotocol/sdk/types.js";

// 1. サーバーインスタンスの生成
const server = new Server(
  { name: "weather-server", version: "1.0.0" },
  { capabilities: { tools: {} } }
);

// 2. 利用可能なツールの一覧を返す
server.setRequestHandler(ListToolsRequestSchema, async () => {
  return {
    tools: [
      {
        name: "get_weather",
        description: "指定した都市の現在の天気を取得します",
        inputSchema: {
          type: "object",
          properties: {
            city: { type: "string", description: "都市名（例: Tokyo, Osaka）" }
          },
          required: ["city"]
        }
      }
    ]
  };
});

// 3. ツールの実行ハンドラー
server.setRequestHandler(CallToolRequestSchema, async (request) => {
  if (request.params.name === "get_weather") {
    const city = String(request.params.arguments?.city);
    return {
      content: [
        {
          type: "text",
          text: `${city} の天気は「晴れ」、気温は 24℃ です。`
        }
      ]
    };
  }
  throw new Error("Unknown tool");
});

// 4. Stdio トランスポートで起動
const transport = new StdioServerTransport();
await server.connect(transport);
----

[IMPORTANT]
====
MCP サーバーのツール名や説明文（description）は、AI モデルが「どのツールを呼ぶべきか」を推論するための最重要情報となります。わかりやすく具体的な説明を記述することが高精度な動作の鍵です。
====

'''

== 運用時のセキュリティとデバッグ Tips

=== 1. API トークンや認証情報の安全な管理
* トークンを `mcp_config.json` に平文でコミットしないよう、環境変数（例: `process.env.GITHUB_PERSONAL_ACCESS_TOKEN` や `${localEnv:TOKEN}`）経由で渡すように構成します。
* 読み取り専用で十分な場合は、DB や API の接続ユーザーを「ReadOnly 権限」に絞ることで、AI による意図しない更新・削除事故を未然に防止できます。

=== 2. 登録されている MCP サーバーの動作確認
Antigravity や CLI では、以下の方法で接続状態や公開されているツール一覧を確認できます：

* **CLI での確認**: `agy mcp list` またはログファイルから接続ステータスを確認
* **UI での確認**: エージェント画面のメニュー（`...`） > **MCP Servers** から有効なツール一覧とスキーマを一覧表示

'''

== まとめ：MCP がもたらす未来

Model Context Protocol（MCP）の登場により、AI エージェントのエコシステムは以下のように進化しています：

* **ツールの再利用性向上**: 1 つの MCP サーバーを作れば、様々なエージェント環境ですぐに使える
* **安全な境界設計**: ツール呼び出しや権限管理を標準仕様のもとで制御できる
* **社内データアクセスの標準化**: データベースや社内 API を MCP 化することで、セキュアに AI から活用できる

AI エージェントの能力を最大限に拡張するために、ぜひ MCP の導入や自作サーバーの開発に挑戦してみてください！

'''
