== はじめに

AI コーディングエージェントを活用していく中で、次のような悩みにぶつかったことはないでしょうか？

* 「毎回チャットに『〇〇の手順は〜〜〜』と長文の手順書をコピペするのが面倒」
* 「プロジェクトのルールファイル（`AGENTS.md`）に手順書を全部書き込んだら、プロンプトのトークン消費が跳ね上がり、AI の回答精度が落ちてしまった」

このジレンマを根本から解決するのが、**Agent Skills（エージェントスキル）** の仕組みです。

[TIP]
====
Skills は、AI エージェントにとっての **「手順書（Runbook）」「カンペ（Cheatsheet）」** です。
必要なときだけピンポイントでメモリ（コンテキスト）に読み込まれるため、トークンを節約しながら複雑な業務フローを確実に実行させることができます。
====

'''

== Rules と Skills の違い

Antigravity などのカスタマイズ機能には主に **Rules（ルール）** と **Skills（スキル）** が存在します。これらは用途によって明確に使い分けます。

[cols="1,2,2", options="header"]
|===
| 項目 | Rules (`AGENTS.md`) | Skills (`skills/<name>/SKILL.md`)
| **役割** | 常時適用される規約・方針 | 特定のタスク時に実行する作業手順（Runbook）
| **読み込みタイミング** | 常にコンテキストに注入 | 該当するタスクが発生した時だけオンデマンドで読み込み
| **主な用途** | コーディング規約、禁止事項、コミット命名則 | デプロイ手順、障害調査、DB マイグレーション、記事執筆フロー
| **トークン消費** | 常に消費 | 必要な時だけ最小限消費
|===

'''

== なぜ Skills は強力なのか？（Progressive Disclosure）

Skills が優れている最大の理由は、**Progressive Disclosure（段階的開示）** という設計思想にあります。

[source,text]
----
[ 初期状態 (トークン消費: 極小) ]
  AI エージェントのコンテキストには、スキルの「名前」と「短い説明文（description）」だけを注入
  例: "deploy-staging: ステージング環境へのデプロイとヘルスチェックを行う"

       │
       │ ユーザーが「ステージングにデプロイして」と指示
       ▼
[ スキル発動時 (オンデマンド読み込み) ]
  AI が関連するスキルを自律的に検知し、`SKILL.md` の詳細手順を初めて読み込む

       │
       │ さらに詳細な仕様が必要な場合
       ▼
[ 深掘り参照 ]
  `references/` フォルダ配下のドキュメントや `scripts/` を必要に応じて読み込み・実行
----

この仕組みにより、何十・何百もの業務手順（数千〜数万行のマニュアル）を用意しても、AI の初期コンテキストを一切圧迫することなく、必要なときに即座に取り出して実行できます。

'''

== Skills のディレクトリ構成

スキルは、プロジェクトの `.agents/skills/<skill_name>/`（またはグローバルの `~/.gemini/config/skills/`）配下にディレクトリとして配置します。

[source,text]
----
.agents/skills/my-specialized-skill/
├── SKILL.md          # 【必須】メイン指示書（YAML フロントマター付き）
├── scripts/          # 【任意】エージェントが実行できる補助スクリプト
├── examples/         # 【任意】期待するコード例・実装サンプル
├── resources/        # 【任意】テンプレートやアセットファイル
└── references/       # 【任意】詳細な仕様書やマニュアル
----

=== 1. `SKILL.md` の基本フォーマット

`SKILL.md` の先頭には、必ず `name` と `description` を含む YAML フロントマターを記述します。

[source,markdown]
----
---
name: hugo-blog-publisher
description: >-
  Hugo ブログの新規記事作成、AsciiDoc のフォーマット検証、ビルドおよび GitHub へのデプロイ・プッシュ手順を実行する際に使用する。
---

# Hugo Blog Publishing Workflow

このスキルは、Hugo ブログで新しい記事を公開する際の一連の手順をガイドします。

## 実行手順

1. **記事の配置確認**
   - 記事は `content/posts/YYYY/MM/<slug>/index.adoc` に配置されているか確認します。
2. **ビルドテスト**
   - `hugo --minify` を実行し、エラーがないことを確認します。
3. **コミット & プッシュ**
   - コミットメッセージは `feat(post): ...` の形式で作成し、リモートへプッシュします。
----

[IMPORTANT]
====
フロントマターの **`description`** は最も重要なフィールドです！
エージェントはユーザーのプロンプトとこの `description` を照合して「このスキルを発動すべきか」を判断します。「何をするスキルか」「いつ使うべきか」を三人称で明確に記述してください。
====

'''

== 実践：実用的なスキルを作ってみる

例として、データベースのマイグレーションと整合性チェックを行う `db-migration` スキルを作成してみましょう。

=== 1. ディレクトリと補助スクリプトの作成

[source,bash]
----
mkdir -p .agents/skills/db-migration/scripts
----

`.agents/skills/db-migration/scripts/validate.sh`:
[source,bash]
----
#!/usr/bin/env bash
# マイグレーション適用前のスキーマ整合性チェック
echo "Checking database connection..."
pg_isready -h localhost -p 5432
----

=== 2. `SKILL.md` の作成

`.agents/skills/db-migration/SKILL.md`:
[source,markdown]
----
---
name: db-migration
description: >-
  データベースの新規マイグレーション作成、適用、およびロールバック確認を行う際に使用する。
---

# Database Migration Procedure

## 前提条件
- Docker コンテナでローカル DB が起動していること。

## 実行手順

1. **整合性チェック**
   - [validate.sh](./scripts/validate.sh) を実行して接続を確認します。
2. **マイグレーション実行**
   - `npm run migrate:up` を実行します。
3. **検証ステップ**
   - `npm run test:db` を実行し、既存データとの整合性をテストします。
4. **問題発生時**
   - エラーが発生した場合は即座に `npm run migrate:down` でロールバックし、エラーログを報告してください。
----

エージェントに「DBのマイグレーションを流して」と頼むと、エージェントはこの `SKILL.md` を読み込み、スクリプトの実行から検証、ロールバックの担保まで確実に行ってくれます。

'''

== 高品質な Skill を作成する 4 つのベストプラクティス

=== 1. 汎用知識は省き、プロジェクト固有の「差分」に集中する
「Git のコミットとは何か」のような AI が既に知っている一般知識は書かず、「当プロジェクト特有のディレクトリ配置」「必須のチェックコマンド」など、固有のルール・手順に絞って記述します。

=== 2. 長大なマニュアルは `references/` に分離する
数十ページの API ドキュメントやスキーマ一覧は、`SKILL.md` に直接埋め込まず `references/api-spec.md` に切り出し、必要なときだけリンク経由で読み込ませます。

=== 3. 複雑なコマンドは `scripts/` にカプセル化する
複数行のシェルコマンドや正規表現パイプを AI にプロンプト経由で組み立てさせるより、`scripts/` に堅牢なシェルスクリプトを用意してそれを呼び出させる方が、実行の確実性が大幅に上がります。

=== 4. 「検証（Validation）ステップ」を必ず含める
「デプロイコマンドを叩いて終わり」ではなく、「ヘルスチェック URL にアクセスして 200 OK を確認する」「ログにエラーが出ていないことを確認する」といった完了検証のステップを明記することで、エージェントの自律的な品質担保が可能になります。

'''

== 発展：スキルをチームや複数プロジェクトで共有する

作成したスキルを複数のリポジトリやチーム全体で共有・配布したい場合は、以下の 2 つの方法が有効です：

1. **`skills.json` による外部パス参照**
   `.agents/skills.json` を配置し、共通リポジトリや共有フォルダのパスを指定することで、複数プロジェクトから同じスキルセットを読み込めます。
2. **Agent Plugins によるパッケージ化**
   スキルだけでなく、関連するルール（`AGENTS.md`）や専用の MCP サーバーを 1 つにバンドルして配布したい場合は、**Agent Plugins** としてパッケージ化するのがベストです。

'''

== まとめ

Agent Skills は、AI エージェントを「ただの一般的なチャット AI」から**「自社の業務プロセスや運用 Runbook を熟知した専属エンジニア」**へと進化させるための強力な基盤です。

* **トークンを無駄遣いしない Progressive Disclosure**
* **Git でチーム共有できるポータビリティ**
* **スクリプトや検証手順による高い信頼性**

まずはチーム内で頻繁に行う「いつもの作業手順」を 1 つ、`.agents/skills/` に書き起こしてみることから始めてみてください！

'''
