== はじめに

Google Antigravity（AGY）などの高度な AI コーディングエージェントを活用する際、プロジェクト固有のコーディング規約（Rules）、手順書や実行知識（Skills）、外部ツール連携（MCP Server）、ライフサイクル実行（Hooks）などを設定することが一般的になってきました。

しかし、これらのカスタマイズが増えてくると、以下のような課題が生じます：

* チームメンバー全員に同じルールやスキルを共有・展開するのが大変
* プロジェクトごとに同じ MCP 設定やスクリプトをコピー＆ペーストしている
* 一連の開発環境セットアップをワンタッチで配布・切り替えしたい

こうした課題を解決するために用意されているのが、**Agent Plugins（エージェントプラグイン）** の仕組みです。

[TIP]
====
Plugins を活用すると、複数の Skills・Rules・Hooks・MCP を 1 つの「配布可能パッケージ」としてまとめ、チームやプロジェクト間で手軽に共有できるようになります。
====

'''

== Agent Plugins とは？

Agent Plugins は、Antigravity の各種カスタマイズ要素を 1 つのディレクトリにパッケージングした配布単位です。

[cols="1,2,2", options="header"]
|===
| カスタマイズ種別 | 単体での役割 | プラグイン内での扱い
| **Skills** | 特定のタスク手順やツールの使い方 | プラグイン専用のスキルとして同梱
| **Rules (`AGENTS.md`)** | コーディング規約や制約ルール | プラグイン有効時に自動マージ
| **MCP Servers** | 外部ツール・API 連携 | プラグイン専用のサーバーとして自動起動
| **Hooks** | ライフサイクルイベント時のコマンド実行 | プラグインの動作フックとして登録
|===

=== プラグインの 3 つのメリット

1. **一括インポート・管理**
   複数の設定ファイルをバラバラに配置する必要がなく、プラグインフォルダを配置するだけで内部のすべての機能が自動認識されます。
2. **名前空間（Namespacing）による衝突防止**
   プラグインごとに名前空間が分離されるため、他のプラグインやグローバル設定とツール名・スキル名が競合しません。
3. **柔軟な有効化 / 無効化**
   プロジェクトやタスクのフェーズに応じて、CLI や設定ファイルからプラグイン単位で簡単に ON/OFF を切り替えられます。

'''

== プラグインのディレクトリ構造

プラグインは、`.agents/plugins/` またはプロジェクトルートの `plugins/` フォルダ配下に作成します。

[source,text]
----
plugins/my-team-plugin/
├── plugin.json       # 【必須】マニフェストファイル
├── mcp_config.json   # 【任意】プラグインが提供する MCP サーバー設定
├── hooks.json        # 【任意】ライフサイクルフック設定
├── rules/            # 【任意】プラグイン固有のルール（AGENTS.md 推奨）
│   └── AGENTS.md
└── skills/           # 【任意】プラグインが提供するスキル群
    └── deploy-helper/
        └── SKILL.md
----

=== 1. マニフェストファイル (`plugin.json`)

プラグインの定義ファイルです。基本的にはプラグイン名を宣言するシンプルな構成です。

[source,json]
----
{
  "name": "team-developer-kit",
  "description": "チーム共通の開発・デプロイ支援プラグイン",
  "version": "1.0.0"
}
----

[NOTE]
====
プラグインを標準で無効状態（OFF）で配布したい場合は、`"disabled": true` を指定することも可能です。
====

=== 2. ルールの同梱 (`rules/AGENTS.md`)

プラグインが有効化されたときだけ適用したいコーディング規約や方針は、`rules/AGENTS.md` に記述します。

[source,markdown]
----
# Team Standards

- すべてのコミットメッセージは Conventional Commits 形式に従ってください。
- エラーハンドリングは必ず呼び出し元にエラーをラップして返してください。
----

=== 3. スキルの同梱 (`skills/<name>/SKILL.md`)

プラグイン固有の実行手順書（Skill）を配置します。プログレッシブ・ディスクロージャー（必要な時だけ読み込む仕組み）により、コンテキストを圧迫しません。

'''

== 実践：チーム用プラグインを作ってみる

例として、社内ツール連携とデプロイ手順をまとめた `devops-toolkit` プラグインを作成する手順を見てみましょう。

=== ステップ 1: ディレクトリとマニフェストの作成

[source,bash]
----
mkdir -p .agents/plugins/devops-toolkit/skills/deploy-staging
mkdir -p .agents/plugins/devops-toolkit/rules
----

`.agents/plugins/devops-toolkit/plugin.json` を作成します：

[source,json]
----
{
  "name": "devops-toolkit",
  "description": "ステージング環境へのデプロイとインフラ操作プラグイン"
}
----

=== ステップ 2: スキル (`SKILL.md`) を追加

`.agents/plugins/devops-toolkit/skills/deploy-staging/SKILL.md` を作成します：

[source,markdown]
----
---
name: deploy-staging
description: ステージング環境へのデプロイ手順とヘルスチェックを実行する
---

# Deploy Staging Workflow

1. `git status` で作業ツリーがクリーンであることを確認します。
2. `./scripts/deploy.sh staging` を実行します。
3. デプロイ完了後、`curl -f https://staging.internal/healthz` で疎通確認を行います。
----

=== ステップ 3: 外部ツール（MCP）の定義

プラグインから専用の MCP サーバーを提供したい場合は、`mcp_config.json` を配置します：

[source,json]
----
{
  "mcpServers": {
    "infra-cli": {
      "command": "node",
      "args": ["/opt/infra-tools/mcp-server.js"]
    }
  }
}
----

'''

== プラグインの管理と切り替え（CLI 操作）

`agy` CLI では、プラグインの確認や有効化・無効化をコマンドで簡単に行えます。

=== 登録されているプラグインの一覧表示

[source,bash]
----
agy plugin list
----

=== プラグインの有効化・無効化

[source,bash]
----
# プラグインを有効化
agy plugin enable devops-toolkit

# プラグインを無効化
agy plugin disable devops-toolkit
----

[IMPORTANT]
====
プラグインの有効/無効設定は各ユーザーのローカル設定（`config.json`）に記録されるため、プラグイン本体のファイルを汚さずに個人の環境に合わせて切り替えられます。
====

'''

== プラグインをパッケージ化して共有・配布する方法

作成したプラグインは、チーム内や複数プロジェクト間で共有・配布することで真価を発揮します。Antigravity では主に以下の 3 つのアプローチで共有できます。

=== 1. プロジェクトリポジトリに直接同梱して共有（チーム内共有）

最もシンプルで手軽な方法は、プロジェクトの `.agents/plugins/` 配下にプラグインを配置し、Git リポジトリにそのままコミットして共有する方法です。

[source,text]
----
my-project/
├── .agents/
│   └── plugins/
│       └── team-tools/
│           ├── plugin.json
│           ├── rules/
│           │   └── AGENTS.md
│           └── skills/
│               └── code-review/
│                   └── SKILL.md
----

* **メリット**: 新しいチームメンバーがリポジトリをクローンするだけで、追加の設定なしにプラグインが自動ロードされます。
* **おすすめ用途**: そのプロジェクト固有のコーディング規約やレビュー手順、デプロイワークフローの共有に最適です。

=== 2. 独立した共有リポジトリ + `plugins.json` による参照（組織・全社横断共有）

複数のプロジェクトで共通のプラグインを使い回したい場合、プラグイン専用の Git リポジトリ（例: `company-agent-plugins`）を用意し、各プロジェクトの `.agents/plugins.json` で読み込む構成が便利です。

`.agents/plugins.json` の設定例：

[source,json]
----
{
  "entries": [
    {
      "path": "tools/shared-plugins",
      "include_only": ["devops-.*", "security-check"]
    },
    {
      "path": "~/shared/my-company-plugins"
    }
  ],
  "inherits": [
    {
      "path": "/opt/company/base-plugins.json"
    }
  ]
}
----

==== パス解決のルール
`plugins.json` の `path` フィールドは以下のように柔軟に解決されます：

* **相対パス** (`tools/...`): プロジェクトルート（`.git` があるディレクトリ）からの相対パス
* **ホーム相対パス** (`~/...`): 実行ユーザーのホームディレクトリからの相対パス
* **絶対パス** (`/...`): システムの絶対パス

[TIP]
====
Git Submodule や社内パッケージマネージャー等で共通プラグインリポジトリを各プロジェクトの `tools/` 配下に配置し、`.agents/plugins.json` で相対指定するのが組織内での運用において最も堅牢で再現性の高いパターンです。
====

=== 3. グローバル設定での共有（マシン・個人共通）

自分専用の便利ツールやスキルを全プロジェクトで使いたい場合は、グローバル設定ディレクトリに配置します。

* **配置先**: `~/.gemini/config/plugins/<plugin-name>/`
* **動作**: どのプロジェクトを開いても自動的にプラグインが読み込まれます。

'''

== まとめ

Agent Plugins を活用することで、以下のような恩恵が得られます：

* **チームのオンボーディングが爆速になる**: `.agents/plugins/` をリポジトリにコミットしておくだけで、新メンバーも同じ AI 開発環境が手に入る
* **関心の分離と再利用性**: 「フロントエンド用プラグイン」「DevOps用プラグイン」のように役割ごとにモジュール化できる
* **クリーンなコンテキスト**: 必要なプラグインだけを有効化し、AI エージェントの性能を最大限に引き出せる

AI エージェントを単なるチャットツールとしてではなく、「チーム専用の自律型エンジニア」として育てていくために、ぜひ Agent Plugins を活用してみてください！

'''
