== はじめに

現代のサイバーセキュリティにおいて、ファイアウォールやアンチウイルスによる「侵入防止（境界防御）」だけで 100% 防ぎ切ることは極めて困難になっています。

高度なサイバー攻撃（APT 攻撃など）に対処するためには、**「攻撃者は既に侵入している」という前提に立ち、侵入後の攻撃者の行動パターンを素早く検知・対応する** アプローチが不可欠です。

この「攻撃者の行動パターン」を網羅的に体系化し、世界中のセキュリティエンジニアやアナリストの間でデファクトスタンダード（共通言語）となっているフレームワークが、**MITRE ATT&CK®（Adversarial Tactics, Techniques, and Common Knowledge）** です。

[TIP]
====
MITRE ATT&CK は、米国連邦政府支援の非営利研究機関である **MITRE 社** が 2013 年から研究・公開している、サイバー攻撃技術に関するオープンなナレッジベースです。
====

'''

== 誕生の背景：「後侵入行動」への視点転換

かつてのセキュリティ研究では「どのように侵入するか」が議論の中心でした。しかし、2010 年代初頭に MITRE 社内で実施されたレッドチーム（攻撃側）とブルーチーム（防御側）の模擬対戦プロジェクトを通じて、新たな課題が浮き彫りになりました。

* 侵入手法自体は多様化・高度化し続けており、侵入を完全に防ぐことは不可能
* 本当に重要なのは、**「侵入した後の攻撃者の挙動（post-compromise behavior）」を観測・整理し、防御側に何が見えていて何が見えていないかを把握すること**

この「後侵入行動の可視化」を目的に作成され、2015 年に無償公開されたのが ATT&CK の原点です。

'''

== ATT&CK を構成するコア要素：TTPs

ATT&CK の中心となるのが、**TTP（Tactics, Techniques, Procedures）** と呼ばれる階層構造です。

[cols="1,2,3", options="header"]
|===
| 階層 | 意味 | 具体例
| **Tactics（戦術）** | 攻撃者の「目的」（Why） | 初期侵入（Initial Access）、権限昇格（Privilege Escalation）、情報窃取（Exfiltration）
| **Techniques（技術/手法）** | 目的を達成する「具体的なやり方」（How） | 資格情報の窃取（Credential Dumping）、標的型メール添付（Spearphishing Attachment）
| **Procedures（手順）** | 実際の攻撃者グループが実行した「詳細な手順・記録」 | 「攻撃グループ APT29 が Mimikatz を用いてメモリ（LSASS）から平文パスワードを抽出した」
|===

さらに、技術をよりきめ細かく分類した **Sub-techniques（サブテクニック）** も用意されており、抽象度の高い「戦術」から具体的な「コマンド実行手順」までを一気通貫でマッピングできます。

'''

== 3 大ドメインとプラットフォーム

ATT&CK では、攻撃対象となる環境ごとに 3 つの **Domain（ドメイン）** が定義されています。

1. **Enterprise（エンタープライズ）**
   * 企業の IT 環境やクラウドインフラを対象とした最も標準的なドメイン。
   * 対象プラットフォーム: Windows, macOS, Linux, Cloud (AWS / Azure / GCP), SaaS, Office 365, Identity (Active Directory 等)
2. **Mobile（モバイル）**
   * スマートフォンやタブレット端末（Android, iOS）を対象としたドメイン。
3. **ICS（産業制御システム）**
   * 工場、電力、水道、ガスなどの重要インフラ（SCADA, PLC 等）を対象としたドメイン。

'''

== 防御に活かすための構成要素

ATT&CK は単なる攻撃カタログではありません。防御側（ブルーチーム）が対策を講じるための情報が密接に紐づけられています。

[source,text]
----
[ 攻撃側 (Attack Lifecycle) ]
  Tactics (戦術)  ──>  Techniques (手法)  ──>  Procedures (事例)
                            │
                            │ 紐づけ
                            ▼
[ 防御側 (Defense & Visibility) ]
  - Data Sources (どのログを収集すべきか: プロセス生成, 認証ログ 等)
  - Detection    (どうやって検知ルールを作成すべきか)
  - Mitigations  (どうやってリスクを予防・緩和すべきか: 最小権限, MFA 等)
----

* **Data Sources（データソース）**: 攻撃を検知するために必要な生の観測情報（例: Process Creation, File Modification, Network Traffic）。
* **Detection（検出）**: 該当テクニックを検知するためのロジックや分析アプローチ。
* **Mitigations（緩和策）**: 攻撃が成功する確率を下げるための予防的構成やセキュリティ設定。

'''

== ATT&CK を使いこなす周辺ツール & エコシステム

ATT&CK の真価は、オープンソースの周辺ツールやフレームワークと組み合わせることで発揮されます。

=== 1. ATT&CK Navigator
ATT&CK のマトリクスを Web ブラウザ上で直感的に可視化・色分けできるツールです。
自社の検知カバレッジをヒートマップとして表示したり、複数レイヤーを重ね合わせて「特定の攻撃グループ（例: APT29）が使う手法のうち、自社で検知できる領域」を視覚的に比較できます。

=== 2. DeTT&CT（Detect Tactics, Techniques & Combat Threats）
オランダの Rabobank 社が開発した、ATT&CK を**「防御視点」**で定量化するためのフレームワークです。
自社で収集しているログ（データソース）から「可視性スコア」を算出し、SIEM や EDR の検知ルールから「検出スコア」を算出して、自社セキュリティ体制の**「防御ギャップ（死角）」**を客観的に浮き彫りにします。

=== 3. D3FEND（Defensive Countermeasure Knowledge Base）
MITRE 社が開発している、**「防御側の技術」**を体系化したオントロジー・フレームワークです。
ATT&CK の各攻撃手法に対して、「どのような防御技術（例: Process Spawn Analysis, Inbound Traffic Filtering）で対抗できるか」が対応付けられています。

=== 4. mitreattack-python
ATT&CK のデータ（STIX 形式）を Python プログラムから直接操作・検索するための公式ライブラリです。
セキュリティツールの自動化パイプラインや、自社ログと ATT&CK の自動突合スクリプトの開発に活用できます。

=== 5. TRAM（Threat Report ATT&CK Mapper）
自然言語処理（NLP）や機械学習を用いて、英語のサイバー脅威インテリジェンス（CTI）レポートから ATT&CK の TTP を自動抽出・マッピングする支援ツールです。

'''

== 実践：セキュリティ運用に ATT&CK を組み込む 3 ステップ

=== ステップ 1: 収集ログ（データソース）の棚卸し
まずは自社の環境で「どのデータソースが取れているか」（Windows Event 4688 / Sysmon / EDR / クラウド監査ログ等）をリストアップし、可視性の範囲を確認します。

=== ステップ 2: 検出能力のスコアリングとギャップ分析
DeTT&CT などのツールを活用し、「ログは取れているが検知ルールがない手法」や「そもそもログが取れておらず完全に死角になっている手法」を可視化します。

=== ステップ 3: 脅威インテリジェンスに基づいた優先順位付け
自社の業界・地域を標的にする既知の攻撃グループ（Groups）やキャンペーンを調査し、それらが多用する TTP から優先的に検知ルールや緩和策を導入します。

'''

== まとめ

MITRE ATT&CK は、攻撃者の行動を構造化することで、**「何が起きていて、自分たちはどこまで見えており、次に何を対策すべきか」** を組織全体で共通理解するための強力なプラットフォームです。

* 攻撃の全体像を捉える **TTPs**
* ログ収集と検知設計の指針となる **Data Sources & Detection**
* 防御体制を客観的にスコアリングする **DeTT&CT / D3FEND 連携**

攻撃手法のカタログとして眺めるだけでなく、ぜひ自社のログ設計や SOC / CSIRT の検知力向上に実践的に役立ててみてください！

'''
