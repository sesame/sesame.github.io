言語のバージョンマネージャー（`nvm`, `pyenv`, `asdf` 等）でホストマシンのシェル設定が複雑化するのを避けるため、個人開発も含めて Dev Containers ベースの開発環境に寄せています。実際に運用して感じたメリットをまとめました。

---

## 1. ホストPCを汚さない

Go、Node.js、Ruby などの言語ランタイムや CLI ツールをすべてコンテナ内に閉じ込めることで、ホストマシンにインストールするツールを最小限（Docker と VS Code のみ）に保てます。

プロジェクトが終わればコンテナとイメージを削除するだけで済み、不要な依存関係がマシンに残りません。

---

## 2. 環境のコード化と再現性

ツールのインストール手順やバージョン指定を `devcontainer.json` と `Dockerfile` に記述しておくことで、環境設定そのものを Git で管理できます。

「README のセットアップ手順が古くて動かない」という問題が起きず、マシンを買い替えた際もリポジトリをクローンして開くだけで同じ環境が立ち上がります。

---

## 3. AI エージェントの実行サンドボックス

Antigravity などの AI コーディングエージェントにシェルコマンドの実行を任せる場合、ホストOS上で直接動かすのは誤操作や環境破壊のリスクがあります。

コンテナ内であれば、万が一意図しないファイル変更やパッケージインストールが発生してもホストに影響がなく、安全に自律ループを回せます。
